# Spool Studio v3.0.2

This release adds full support for the new paxx12 Spoolman / RFID workflow used by Snapmaker U1 firmware v1.5.x and newer.

Tested with **paxx12 Extended Firmware v1.5.2-paxx12-21**.

## Why the Material Modifier field exists

I wanted to keep information such as the `+` in `PLA+`, while still staying compatible with the new paxx12 firmware logic.

The firmware expects printer-safe material values such as `PLA`, `PETG`, `ABS`, etc. A value like `PLA+` can cause problems because it is not a valid printer material in this workflow.

To avoid losing that information, Spool Studio now supports an optional Spoolman filament extra field:

`material_modifier`

Example conversion:

`PLA+ - Silk`

becomes:

- Material: `PLA`
- Material modifier: `Plus`
- Variant: `Silk`

This keeps the printer-compatible material clean, while Spool Studio can still display and preserve the full meaning of the filament.

Spool Studio can create the required `material_modifier` field in Spoolman after confirmation. If the field is not created, the app can still be used, but material modifiers such as `Plus` or `HS` cannot be preserved separately.

## UID based tag workflow

The new workflow no longer relies on the old tag content as the primary link to a spool.

Instead, the physical UID of the RFID/NFC tag is used.

Workflow:

1. Spool Studio reads the physical UID from the tag.
2. The UID is stored in the Spoolman spool record under `extra.card_uids`.
3. When the printer reads the tag, the paxx12 firmware can look up the matching spool in Spoolman using this UID.
4. The spool data then comes from Spoolman, while the tag acts as the physical identifier.

This makes the link between tag, spool and Spoolman record much more reliable.

## Converting old v2 tags and Spoolman data

Spool Studio v3 can help migrate data from the older v2 workflow to the new paxx12-compatible format.

When an old tag is read, Spool Studio can detect the old format and offer a conversion.

The conversion can:

- read the old tag data
- identify the matching Spoolman spool
- store the physical tag UID in `extra.card_uids`
- convert old material strings into the new structure
- preserve modifiers such as `Plus`
- write the new paxx12-compatible tag format

When a tag is read and rewritten with Spool Studio v3, the physical tag UID is stored in Spoolman under `extra.card_uids`. After that, the spool is fully part of the new UID-based paxx12 workflow.

In short: reading an old tag and writing it again with Spool Studio v3 stores the tag UID in Spoolman and updates the tag to the new paxx12-compatible format.

There is also a Settings tool to scan existing Spoolman filament records and choose which records should be converted. This is intentionally selectable, so test records or special cases do not need to be changed automatically.

The Spoolman legacy conversion tool can be found here:

`Settings -> Show Spoolman Info -> Scan legacy Spoolman materials`

Spool Studio scans existing Spoolman filament records and shows a selectable list. You can choose which records should be converted to the new v3 / paxx12-compatible structure.

## Printer command check

Spool Studio now checks whether the required paxx12 G-code command is actually available:

`SET_SPOOL_ID`

This command was only available after enabling:

`AFC Lite via Fluidd/Mainsail`

on the paxx12 firmware configuration page and restarting the printer services.

If `SET_SPOOL_ID` is missing, Spool Studio shows this in the Moonraker info section:

`Settings -> Show Moonraker Info`

This helps detect an incomplete printer configuration before trying to assign spools from the app.

## Toolhead Status: App labels and SpoolLink

The Toolhead Status dialog has two display modes:

- `App labels`
- `SpoolLink`

`App labels` shows the filament names as Spool Studio builds them for the app UI. This includes additional information such as the optional `Material modifier`, for example showing `PLA+ / Silk` even though the printer-safe material is stored as `PLA`.

`SpoolLink` shows the data as reported by the paxx12 Spoolman / SpoolLink integration. This is useful for checking what the printer firmware currently sees and receives from its Spoolman integration.

In short:

- `App labels` = Spool Studio view with preserved app-side labels and modifiers
- `SpoolLink` = printer / firmware reported view

This helps compare whether the app-side data and the printer-side SpoolLink data match as expected.

## Manual assignment list

The manual `Assign spool` dialog only shows spools that already use the new paxx12-compatible Spoolman field layout.

Spools without a stored tag UID are still selectable, but they are marked with `No UID stored`. These manual assignments can work, but the printer may replace them when it reads an RFID tag and resolves the spool through UID-based Spoolman lookup.

If a spool has no UID yet, read the tag and write it again with Spool Studio v3. This stores the physical tag UID in Spoolman and makes the spool fully compatible with the new UID-based workflow.
